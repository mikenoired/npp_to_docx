# Паспорта кадров: релизный интерфейс

Приложение для инженера, который собирает паспорта SVG-кадров с описаниями KKS
и затем находит нужный кадр по подмодели. Главный сценарий: выбрать исходные
данные, проверить состав пакета, создать DOCX и перейти к результатам.

## Направление

Компактная рабочая станция. Холодные нейтральные поверхности, один синий акцент,
чёткие строки и устойчивое расположение действий. Состояние показывается и
словами, и цветом. Никаких декоративных графиков или выдуманных показателей.

| Роль | Светлая тема | Тёмная тема |
|---|---|---|
| Рабочий фон | `#F1F4F7` | `#151E27` |
| Поверхность | `#FFFFFF` | `#1C2834` |
| Основной текст | `#152C40` | `#E0E9EF` |
| Подписи | `#65788B` | `#96A8B8` |
| Акцент | `#176E8A` | `#75BDD0` |
| Разделители | `#DCE4EB` | `#304151` |

Заголовки: Avenir Next на macOS, Bahnschrift на Windows, DejaVu Sans на Linux.
Основной текст: системный шрифт, 14 px. Имена SVG, KKS и время: платформенный
моноширинный шрифт, 12–13 px. Основной заголовок 24 px, секции 16 px.
Отступы кратны 4 px; радиус 6–8 px. Контраст и фокус важнее украшений.

## Структура

```text
┌──────────────────┬───────────────────────────────────────────────┐
│ Паспорта         │ Новый пакет                  статус источников│
│ SVG → DOCX       ├───────────────────────────┬───────────────────┤
│                  │ Исходные данные           │ Состав пакета     │
│ Создать паспорта │ База · SVG · Результаты   │ Проверка БД       │
│ Найти кадр       │                           │ Число кадров      │
│ Запуски          │ Параметры обработки       │ Имена SVG         │
│                  │ [Создать паспорта]        │ Формат результата │
│                  ├───────────────────────────┴───────────────────┤
│ Тема · версия    │ Последний запуск · прогресс · время · журнал   │
└──────────────────┴───────────────────────────────────────────────┘
```

Характерная деталь — состав пакета в виде регистра кадров: реальные имена SVG,
состояние двух баз и количество документов. Он объясняет результат до запуска.

Поиск: слева подмодели с количеством вхождений, справа таблица кадров, KKS и
описаний. Результат не маскируется под пустой список до выполнения поиска.
Журнал: отдельный список запусков с временем, результатами, путями и логом;
история сохраняется между сеансами.

## Поведение

- Проверять папки в фоне после изменения ввода, не выполнять файловый обход
  при каждом рендере. Показывать отсутствие файлов и путь к исправлению.
- Основное действие доступно при наличии SVG и обеих баз (CSV или DMP).
  DMP автоматически подготавливается движком; отдельное действие подготовки
  остаётся доступным для повторного использования CSV.
- Сохранять папки, параллелизм, фильтр, лимит и тему.
- Во время обработки блокировать параметры, показывать количество, долю,
  прошедшее время, ошибки и доступ к полному логу. Не прятать сбой за 100%.
- После завершения дать переход к результатам и поиску. Разделять отсутствие
  индекса, отсутствие запроса и отсутствие совпадений.
- Не терять основной запуск при просмотре истории; показывать активность
  в боковой навигации.
- В debug-сборке объяснять медленную обработку и показывать release-команду.
- Поддерживать светлую и тёмную темы, клавиатурный ввод и Enter в поиске,
  независимую прокрутку таблицы, настроек и журнала.

## Проверка направления

Убрана идея декоративного макета DOCX: без настоящего выбранного кадра он
создавал бы ложное впечатление предпросмотра. Вместо него — реальный регистр
исходных файлов. Метрики относятся к конкретному пакету и запуску, а не к
общему рекламному сравнению технологий.
